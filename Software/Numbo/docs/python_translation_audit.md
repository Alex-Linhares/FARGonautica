# Audit: a test-driven translation of Numbo to Python

Date: 2026-10-01. Baseline: the SBCL port in `lisp/src/` (commit `34d382a`), all 14 test groups passing.

## Verdict

**Moderate difficulty, and low risk if it's done differentially.** The program is
small, there's no deep Lisp magic left in it, and we already have a working
oracle (the SBCL port). The hard part isn't writing Python. It's proving the
Python behaves like the Lisp, run for run. That's very doable if we first add
two small hooks to the SBCL port (a shared RNG and a structured trace). Without
them, the best we can do is statistical comparison, which hides bugs.

Rough size: **about 12–15 Ralph-loop items**, similar to loop0001 (12 items,
about 2 h of loop time). Expect 1–3 extra iterations of divergence hunting at
the codelet stage.

## Lisp features the code relies on, and their Python equivalents

| Feature | Uses | Python approach | Risk |
|---|---|---|---|
| `(send obj :msg ...)`, Flavors ivars | 308 | Plain classes and methods. Gettable/settable become attributes | Low |
| Codelets as quoted forms, `(eval (cr-choose ...))` | 13 evals of codelets, 45 `cr-hang` sites in the source plus the codelets attached to pnodes, at least 17 codelet types | Codelet = `(function, args)` tuple, called directly | Low |
| `(eval sym)` to dereference node names (`pnode`, `name`, `op1n`, `cyto-derived-target`, ...) | about 58 | A `world.nodes[name]` registry. Every "variable holding a node" becomes a name lookup | **Medium**: you have to find every place a *symbol* stands in for an object |
| Names built with `concat`/`uconcat` (`node-31`, `cyto-block27-v2`, `:brick1`) | 18 | f-strings into the registry. **Keep the exact upper-case names**, because the trace compares them | Medium |
| Free globals and `setq` | 514 setqs. About 100 proclaimed globals plus 20 names that are global in one place and local in another (`node`, `res`, ...) | One `World` object for the real globals. The "global here, local there" cases (PORTING_NOTES items 7–8) need care: a free `setq node` in a pnode method writes a global the codelets never read | **Medium-high**: a silent behavior change if you get it wrong |
| Franz `/` and `quotient` (truncate), `mod` = CL `rem` | 15 + mod sites | `int(a / b)` / `math.fmod`-style helpers, **not** `//` and `%`, which floor | **High if missed** (wrong for negatives); trivial if centralized |
| `(max)` with no args = 0 | `temperature` | `max(xs, default=0)` | Low (already documented) |
| Franz lexpr `defun check-temperature function ()` | 1 | `*args` | Low |
| **Floats**: SBCL reads `0.9` as *single* float, Franz used doubles | all activation arithmetic | Python floats are doubles. For exact agreement with the SBCL oracle, either (a) run the oracle in double (`*read-default-float-format* 'double-float` for numbo files only), or (b) use `numpy.float32` in Python. **(a) is better**: it's also closer to the 1987 machine | **High**: threshold comparisons on activations decide which codelets get posted |
| Destructive `sortcar` (`sort` on a shared list) | 2 | Python `sorted` never drops elements. The SBCL port sometimes does (PORTING_NOTES item 11: entries lost in about 1 run in 40). For exact agreement, make the Lisp `sortcar` copy first (a documented change; same solve rate) | Medium |
| Sort stability and alphabetical `alphalessp` | 2 | Python sort is stable. Match SBCL's list `sort` (also stable merge sort) on print names | Low |
| `format t` / `print` output | 35 | Keep the exact text. Normalize case and float printing in the comparator, or compare structured events instead (better) | Low |
| `random` | **7 call sites**, all `(random n)` on integers | A shared PRNG (see below) | Low, and it unlocks exact testing |

## The TDD plan: make the SBCL port the oracle

### Step 0: two hooks in the Lisp port (prerequisite, about 1 item)

1. **Shared deterministic RNG.** Only 7 `(random n)` calls exist (coderack ×2,
   codelets ×5). Add an opt-in generator to `franz-compat` (e.g. splitmix64,
   with `n` taken by rejection sampling), defined bit-for-bit so Python can copy
   it. Keep SBCL's default RNG as the default so that `README.md`'s seed 18
   still reproduces.
2. **Structured trace.** An opt-in JSON-lines event log: per iteration, the
   codelet chosen and its args, coderack size, temperature; node created or
   killed; pnet activations at each `refresh-everything`; and the final
   decomposition. `%verbose%` output already covers part of this.

Also pick the float policy (double in the oracle is recommended) and the copying
`sortcar`. With these, **same seed ⇒ same event stream**, and the first
differing line in the trace shows exactly where the Python went wrong.

### Test layers (write each before the code it tests)

1. **Semantics helpers** (from `franz-compat-tests`, 178 checks): truncating
   division, `rem`, `(max)` = 0, alphabetical sort order, name builders.
2. **Pnet data**: a Lisp dump of all 88 pnodes (value, type, neighbors, link
   types, codelets, thresholds) compared field by field with the Python table.
3. **Spreading activation**: snapshot before and after `spread-activation-in-pnet`
   from the oracle, compared to within ε, or exactly if both use doubles.
4. **Coderack** (from `coderack-tests`, 65 checks), plus an exact
   draw-sequence test with the shared RNG.
5. **Codelets, one at a time**: for each of the 17 codelet types, capture
   (world state before, args, RNG stream) and the world state after, from the
   oracle. These are the core TDD fixtures.
6. **Full runs**: event-stream equality on the 11 chapter puzzles × N seeds,
   with the first divergence reported.
7. **Statistics** (from `validation-tests` and `RESULTS.md`): the solve rates
   and solution sets per puzzle should match, as a final check that still means
   something if exact matching ever has to be relaxed.
8. **Solution checker** (25 checks): port it, or keep the Lisp one as the
   referee.

### Suggested loop order (loop0002)

1. Oracle hooks: shared RNG, JSON trace, double floats, copying sortcar (Lisp side, keeping the existing tests green)
2. Python skeleton, pytest, fixture-capture scripts
3. Semantics helpers
4. Pnet data table (generated and checked)
5. Pnode class and spreading activation
6. Coderack
7. Cytoplasm classes
8. Codelets A: node creation, linking, activation (`create-cyto-node`, `link-to-pnet`, `activate`, `kill-node`, `free-from-pnet`)
9. Codelets B: block search (`look-for-*`, `compare-b-to-t`, `test-if-possible-and-desirable`)
10. Codelets C: decomposition and targets (`decomp+`, `decompi`, `const-bl*`, `replace-target`), plus `temperature` and `decompose`
11. Main loop, `config`, `refresh-everything`, `reactivate-cyto`
12. Full-run trace equality on 11 puzzles × 20 seeds; hunt divergences
13. Solution checker, RESULTS.md reproduction, CLI and README

## Risks, ranked

1. **Float precision** (the SBCL port uses single floats, Python uses doubles). If this isn't settled first, traces will diverge on activation thresholds and look like random bugs.
2. **Global vs. local names** (`node`, `res`, and the 20 names from PORTING_NOTES item 8). A wrong guess silently changes behavior. The codelet fixtures catch it.
3. **Symbols standing in for objects** (`eval` of names). It's easy to miss one and pass an object where a name was expected.
4. **Truncating division and `rem`** on negative numbers (differences in `look-for-diff` and the like can go negative).
5. **Destructive sort behavior** in the SBCL port, a source of unreproducible divergence until it's made copying.
6. The **kill-block gap** and the **reactivate-cyto race** are original 1987 behavior. Python must reproduce them, not fix them, or the trace tests will fail. Fixes belong in a later, separate pass.

## What makes it easier than it looks

- The program is already running, tested and documented. All the archaeology (OCR, dialect, missing coderack) is done.
- No Lisp-only features remain: no macros in the source, no closures stored in data, no `call/cc`, and graphics are stubbed.
- Randomness goes through only 7 call sites.
- `../bricks.py` (an arithmetic tree with Graphviz output) could be reused for visualizing solutions. It isn't needed for the port.
